# 动态主题实施计划

Forge 使用根目录的 Gradle 8.8，运行于 Java 17，NeoForge 使用 `neoforge/` 的 Gradle 9.2.1 和 Java 21。后者共享根目录的 Java、Kotlin 和资源，单独替换入口、部分渲染及平台桥。主题核心放在共享的 `theme` 包中，保持 Java 17，核心不导入 Minecraft、Forge 或 NeoForge 类。

现有原生控件和 `UiScreen` 持有输入、旁白、焦点和生命周期，`UiApiContext` 关闭时释放页面资源。布局是可组合工具，库没有统一的可重建控件树。`UiFrameScheduler` 已提供帧首单调时间。`UiTheme`、`ThemeEffects`、`ThemeSettings` 与 `UiPreferences` 已提供旧版外观和配置入口。用适配方式保留旧配置和二进制接口，避免把新令牌的默认值应用到未选择动态主题的现有页面。

| 阶段 | 实施 | 验证 |
| --- | --- | --- |
| 1 | 核对源集、客户端钩子、已有主题和页面 API | 两端依赖与基线测试 |
| 2 | 不可变主题、类型化令牌、继承、依赖图、快照缓存 | 注册冲突、缺失父级、依赖重算和循环路径 |
| 3 | 嵌套作用域、状态样式、绑定和按所有者合并失效 | 兄弟作用域隔离、重绑、关闭释放 |
| 4 | 单调时间驱动的轨道和过渡策略 | 虚拟时钟、快速打断、队列、取消和暂停 |
| 5 | 依赖声明规则、稳定时间、事件队列、客户端环境 | 无世界／无玩家、规则去抖、回调重入 |
| 6 | 资源包解析、版本化提交、动态调色板与音频 | 错误保留旧快照、乱序提交、调色与对比测试 |
| 7 | 诊断、增量缓存和基准 | 100／1,000／10,000 控件和多令牌变动 |
| 8 | 公共 API、Schema、两端示例和客户端验收 | Forge／NeoForge 构建，记录游戏测试和截图基线 |

主题请求、注册、事件、作用域和失效提交限定在同一客户端线程。后台仅准备不可变资源结果，代际检查通过后才替换注册快照。控件读取已求值的快照。作用域对父级和全局变化保留覆盖语义，事件和属性失效通过各自队列防止回调重入。过渡用当前显示值作为打断的起点，组件交互状态和无障碍在最终属性解析阶段生效。

主要兼容风险为两端加载器事件签名、作用域覆盖后派生值未重算、窗口重布局重复订阅、异步重载倒序提交、旧配置的外观或 API 回归，以及透过玻璃材质实际背景无法由核心推断。双端构建与实际游戏交互分别记录。
