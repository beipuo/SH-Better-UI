# 动态主题基准

2026-11-10，Windows 11，Intel Core i9-14900HX，Java 17，堆为 512 MiB 到 1 GiB。每组预热 80 帧，采集 160 帧。时钟每帧推进 16 ms。每个控件读取一个缓存属性，绑定均匀分布到 100 个令牌，其中每十个绑定有一个需要布局。局部改动只修改四个嵌套分支中的一个。过渡组每三帧打断一次，两端主题各改变 100 个令牌。

```bash
./gradle-install/gradle-8.8/bin/gradle.bat -I gradle/theme-benchmark.init.gradle benchmarkDynamicTheme
(cd neoforge && ./gradlew.bat -I ../gradle/theme-benchmark.init.gradle benchmarkDynamicTheme)
```

命令输出全部组的 CSV，包括墙钟延迟、线程 CPU 时间和分配、进程 GC 次数与时间、属性读取和失效、布局通知、解析和实际求值次数。绘制阶段用每个控件的一次绑定读取表示，布局计数是需要布局的通知次数。该测试不执行 Minecraft 字体测量、着色器或 GPU 绘制。Windows 线程 CPU 计时粒度较粗，较短静态场景可能显示 0。

静态组没有重新解析。10,000 控件的单令牌改动组在 160 帧内只求值 160 个令牌。10,000 控件的过渡组在 160 帧内解析了 53 次新目标，求值 5,300 个令牌，采样帧复用这些结果。该组线程 CPU 平均约 1.17 ms，采样窗口内没有记录到 GC。早期基准中同组每帧约分配 4.59 MB。复用失效队列、状态缓存键和依赖去重标记后，分配降至约 69 KB。两次测量的运行时与后台负载不同，延迟不能用于严格的前后对照。
