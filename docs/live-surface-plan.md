# 自适应实时表面实施计划

目标是在现有 Unified UI Kernel 中提供第三方可用的实时活动、通知和自适应表面。Forge 1.20.1 / 47.4.16 保持 Java 17，NeoForge 1.21.1 / 21.1.251 继续用 Java 21 编译原生层，两端共用 Java 17 契约。

## Phase 0 仓库审计

基线提交 `d87e31e` 已提供 `UnifiedUI.get()`、模块依赖与权限、`StateStore`、事件和中心调度。现有工作区另有 Spatial SDF、主题编辑和图标变更。实时表面复用当前工作区的 Spatial 实现，相关文件保持原有改动。

- `src/kernel/java` 和 `gradle/kernel.gradle` 提供共享 API、生命周期和契约测试源集。
- `ClientUiKernel` 已在原生帧内推进状态、布局、动画和渲染，并追踪 Screen、会话及资源重载代次。两端 `UiClient` 的 Screen Pre 输入可取消，原生 HUD 的鼠标在游戏中被锁定。
- `SpatialUI` 负责场景、SDF 和阴影降级。复用 `Spring` / `InterruptibleAnimation` 的时间积分与连续重定向。旧音乐胶囊有独立使用者，新的音乐示例通过公开 API 发布活动。
- 缺少活动和通知的作用域句柄、主次仲裁、避让注册、内容驱动的 HUD、会话协议和第三方示例。
- 网络注册、Screen 事件字段及 HUD 帧入口按两个 Loader 分别验证。渲染只在物理客户端安装，网络公共代码可由专用服务器加载。输入交互使用拥有鼠标的 Screen。

## 实施和验证顺序

| 阶段 | 工程入口 | 验证条件 |
| --- | --- | --- |
| 1 内核基础 | 沿用已注册服务、模块上下文与原生桥 | 两端运行 `kernelTest`，复核模块和服务契约 |
| 2 状态和活动 | Java 17 活动请求、快照、句柄、所有者和中央调度合并 | 版本去重、后台提交、终结和作用域清理 |
| 3 通知和仲裁 | 通知句柄及基于同一候选集的主次计划 | 去重、最低展示时间、抢占恢复和等待公平性 |
| 4 布局和绘制 | 视口及内容测量、Spatial 场景、主题令牌 | 屏幕边界、紧凑与分栏形态、实际原生绘制 |
| 5 动画和输入 | 统一过渡控制器、已绘制几何、原生输入捕获 | 时间步长、中断、取消、键盘及焦点 |
| 6 空间和同步 | 显式占用、HUD 保留区、双端会话协议 | 避让、版本和容量、失序、重连和服务端授权 |
| 7 双端集成 | Forge 与 NeoForge 各自运行包 | 两端客户端及专用服务端启动证据 |
| 8 示例和文档 | 外部示例模组、接入及配置说明、基准 | 独立消费包、五类场景和可复现报告 |
| 9 最终验证 | 回归、发行 JAR、差异与交付状态 | 记录实际命令、失败和覆盖范围 |

各阶段的构建、原生客户端和服务端结果集中记录在[验证记录](live-surface-verification.md)。公开 API、线程和配置契约见[接入指南](live-surfaces.md)，本次 CPU 和分配采样见[性能报告](live-surface-benchmark.md)。
